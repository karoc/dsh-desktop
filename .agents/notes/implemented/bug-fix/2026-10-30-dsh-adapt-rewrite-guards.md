# Agent Note: dsh-adapt-rewrite-guards

Status: implemented

## Problem

`dsh-adapt` 的自动改写有两处在真实适配轮次里才会暴露的坏结果：① 步骤 2 把适配记录拼在注释块收尾的 `*/` 位置，吃掉了收尾行的前导空格，插入的第一行变成 `  * …` 而后续行是 ` * …`（单行缩进漂移，看起来像人工手改坏；2026-10-30 抬 rc.5 时人工修正过）；② 步骤 3 用 `README.split(旧地板).join(新地板)` 全量替换，把历史叙述一起改掉——例如「2026-10-19 实测 `--version 0.2.1-rc.2 --dry-run`」被改成 rc.5 ⇒ 伪史；词边界反例段（`0.2.1-rc.3` 不命中 `0.2.1-rc.2`）同理。

## Decision

① 适配记录按注释块**收尾行**的缩进对齐：取 `*/` 前的空白 `indent`，内容行写成 `${indent}* <text>`、收尾写回 `${indent}*/`；收尾行含非空白字符时直接报错不写（不再靠“看着像”）。② README 只改**地板语境**的同一行——行内必须同时出现 `地板` / `MIN_DSH_VERSION` / `壳要求 dsh` 三个词之一；其余出现（历史实测、示例命令、词边界反例）原样保留，并在 `note()` 里打印 `跳过 N 处非地板语境（行 …），历史/示例，请人工确认`。dry-run 的计数口径与真实运行一致（只算地板语境命中）。两条都由 `test-automation-gates --only adapt` 新增用例守护：副本地板改旧后跑真实金路径，断言①注释块每行 `startsWith(' * ')`（旧实现首行 `  * ` 必红）、②README 地板行被改而 `--version <旧地板> --dry-run` 原样保留、③输出点名被跳过的行号。
## Alternatives considered

**只加缩进断言、README 继续全量替换**：否决——伪造历史比缩进漂移更严重，而且「换掉所有旧版本号」在任何文档里都等于抹掉取证线索。**用更宽的关键词（如出现 `rc`/`版本` 就替换）**：否决——README 的示例命令与反例段都含这些词，等于没限制。**README 逐句人工改、脚本完全不碰**：否决——现有纪律是「改了 manager 必改 README」的文档同步门禁在 CI 里强制，脚本全不碰会让该门禁经常红，且真实适配轮次会多一步易漏的人工动作。
## Consequences

买到：真实适配轮次的自动改写不再产生「伪史 / 缩进漂移」两类需要人工回修的产物，且被跳过的历史行以行号显式列出（作者知道要不要动）。代价与边界：① 地板语境判定是**启发式**——README 里若出现一条纯 "当前地板 `x`" 但不含三个关键词的句子，会变成"跳过 + 人工确认"，而不是自动改（宁可漏改也不误改）；② 测试里用合成版本 `0.2.0-alpha.9` 保证 README 只有种子行命中，真实仓库的 README 仍需在第一次真实适配时人工确认一次输出里的跳过行号；③ `dsh-adapt` 的第 2 步仍依赖注释块存在且收尾行干净，结构不符时 fail-closed 而不是猜。
